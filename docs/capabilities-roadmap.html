Capabilities and roadmap

What MCPKite supports today, and which FastMCP server capabilities are not exposed in the product yet.

This is a view of current product coverage and areas we may explore, not a release commitment. Items below have no promised delivery dates. MCPKite's support will continue to evolve.

  • Tool authoring
  • Protocol and catalog

Supported today

MCPKite deploys as a long-running application that can host multiple managed MCP servers. Add or edit a server and its capabilities through the workspace instead of redeploying the MCPKite application for each change.

AreaAvailable in MCPKite
ServersWorkspace-managed servers with their own MCP endpoint and normal or bearer-token-protected access.
ToolsOne validated top-level Python function per tool, published to MCP clients when the isolated runner is available.
PromptsReusable text templates with named arguments and workspace-value references.
ResourcesStatic text resources, text URI templates, and private binary files at static URIs, with supported annotations.
TransportStateless Streamable HTTP. Clients do not need to retain protocol session IDs between calls.
Tool executionEach saved Python tool call runs in a short-lived sandbox container with operator-configured limits and restricted network egress.

Tool authoring and context

  • Richer tool schemas and metadata. MCPKite's editor validates a focused set of Python annotations and derives input schemas from the function. It does not expose FastMCP's broader Pydantic/Annotated schema controls, tool titles, tags, icons, arbitrary metadata, or behavioral hints. See FastMCP's tool documentation and icon support.
  • FastMCP context and dependency injection. User-authored sandbox functions do not receive FastMCP's Context or dependency-injected server values. Context-based progress reporting, MCP client logging, and protocol-compatible elicitation are therefore not configurable in MCPKite. See Context, dependency injection, progress, client logging, and elicitation.

Protocol and catalog features

  • Resource subscriptions and change notifications. Clients cannot subscribe to resource updates or receive pushed resource-change notifications from MCPKite today.
  • Argument completions. MCPKite does not let users provide FastMCP completion handlers for prompt arguments or resource-template parameters. See FastMCP completions.
  • MCP-level list pagination. The app paginates its management screens, but does not configure FastMCP's cursor pagination for the MCP tools, prompts, and resources lists. See FastMCP pagination.
  • Tool search and Code Mode. Large catalogs cannot be exposed through FastMCP's search_tools/call_tool discovery pattern. Code Mode, an experimental FastMCP transform that lets a model compose tool calls through code, is also not part of the current MCPKite interface and requires an optional extra. See tool search and Code Mode.

Workflows and server composition

  • Long-running background tasks. MCPKite's tool execution is request-scoped and bounded by sandbox limits; it does not expose FastMCP's task-based background execution. FastMCP Tasks requires the separate fastmcp-tasks package. See FastMCP Tasks.
  • Per-user MCP session state. MCPKite endpoints are stateless and user-authored tools cannot use FastMCP's application-level session state. See FastMCP sessions.
  • Composing other servers. MCPKite creates its own managed servers; users cannot mount or proxy another local or remote MCP server into one of them, or configure custom FastMCP providers. See composition and providers.
  • Component transforms and visibility. There are no per-server controls for namespace transforms, tool transformations, component visibility/version filters, or exposing prompts/resources as tools. See transforms and versioning.
  • Interactive MCP Apps. Tools cannot return interactive UI components to supporting clients. FastMCP Apps requires an optional extra and client support. See FastMCP Apps.
  • Skills over MCP. FastMCP added Skills support in 4.2.0; it is newer than the 4.1.6 runtime inspected for this page and also depends on client support for the Skills extension. MCPKite does not expose it today. See FastMCP Skills.

Security and operations

  • Additional authentication strategies. MCPKite offers per-server bearer tokens, but not FastMCP's OAuth/OIDC providers, OAuth proxies, multiple auth sources, incremental authorization, or identity assertion integrations. Identity assertion is marked beta upstream. See authentication, remote OAuth, OAuth proxy, OIDC proxy, and MultiAuth.
  • FastMCP middleware and authorization policies. MCPKite does not expose per-server FastMCP middleware pipelines, rate-limiting middleware, or component-level authorization rules. See middleware and authorization.
  • Per-server lifecycle and operations settings. Users cannot configure FastMCP-specific lifespan hooks, storage backends, or OpenTelemetry modes/exporters per server. MCPKite's own PostgreSQL, resource-storage, and deployment settings remain available separately. See lifespans, storage backends, and telemetry.
  • Transport choices. MCPKite publishes remote stateless Streamable HTTP endpoints; users cannot choose a per-server transport such as local STDIO. SSE is a deprecated FastMCP transport and is not presented as a roadmap commitment. See FastMCP server transports.

Version and scope notes

The backend container inspected for this review resolves FastMCP 4.1.6. The declared dependency range in backend/requirements.txt is fastmcp>=2.14,<5.0, so another installation may resolve a different version. The list describes MCPKite's current product surface against the inspected 4.1.6 baseline; it does not guarantee identical upstream behavior across every version allowed by that range.

Some upstream capabilities need optional packages, a compatible MCP client, or a protocol version that supports the feature. FastMCP features are not automatically MCPKite features just because they exist in the library.

We will keep this page updated as MCPKite evolves. The items above are areas for consideration, not a prioritized delivery schedule or a promise to implement every upstream feature. FastMCP's full OAuth server is intentionally omitted because its own documentation describes it as an advanced approach most users should avoid; developer/testing utilities and the separate FastMCP Gateway product are outside this user-facing list.
