Deployment and configuration

Prepare the database, browser origin, secrets, object storage, and sandbox boundary before making MCPKite available to users.

On this page

  • Production checklist
  • Core configuration
  • Resource storage
  • Sandbox limits
  • Runtime trust boundaries

Production checklist

  • Serve the application and API over HTTPS; set AUTH_COOKIE_SECURE=true.
  • Set a stable, strong AUTH_JWT_SECRET of at least 32 bytes and a non-default database password.
  • Keep the UI and API on the same site so the existing SameSite=Lax authentication cookies work.
  • Configure exact browser origins in CORS_ALLOWED_ORIGINS; never use * with credentials.
  • Set and securely back up WORKSPACE_SECRET_ENCRYPTION_KEY together with database backups.
  • Use private production object storage, least-privilege storage credentials, and production-grade PostgreSQL backups.
  • Do not expose the runner or Docker socket. Restrict database and administration services to trusted networks.
  • Set the public MCP endpoint origin so the UI shows client-reachable URLs.

Core configuration

Compose reads deployment settings from the root .env; the backend reads private settings from backend/.env; browser-visible Vite settings belong in frontend/.env. Never put secrets in frontend variables: Vite embeds VITE_* values into the browser bundle.

VariablePurpose
POSTGRES_PASSWORDDatabase password; replace the local development default.
AUTH_JWT_SECRETPersistent key for signing authentication tokens; use at least 32 bytes.
AUTH_COOKIE_SECURESet to true when serving over HTTPS.
CORS_ALLOWED_ORIGINSComma-separated exact browser origins allowed to make credentialed requests. Do not use a wildcard.
WORKSPACE_SECRET_ENCRYPTION_KEYBase64-encoded 32-byte key for workspace secrets; keep stable and backed up.
VITE_API_BASE_URLBrowser API prefix; defaults to same-origin /api/v1.
VITE_MCP_ENDPOINT_BASE_URLPublic MCP endpoint origin shown and copied by the UI. Set it to the externally reachable origin.
RESOURCE_STORAGE_PROVIDERs3 or azure_blob for binary resources.

When UI and API use different ports, include the UI's exact origin in CORS settings. The frontend uses credentialed requests. Cross-site cookie authentication is not supported.

Resource storage configuration

Choose one provider and keep its bucket or container private.

VariablePurpose
RESOURCE_S3_BUCKETPrivate S3-compatible bucket.
RESOURCE_S3_REGIONBucket region.
RESOURCE_S3_ENDPOINT_URLOptional S3-compatible endpoint; leave empty for Amazon S3.
AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEYOptional paired credentials; when unset, the AWS SDK credential chain is used.
RESOURCE_AZURE_CONNECTION_STRINGRequired connection string when Azure Blob is selected.
RESOURCE_AZURE_CONTAINERPrivate Azure Blob container name.

Compose starts S3Mock and Azurite for local development only. For S3, configure the bucket and region; remove or empty the endpoint URL for Amazon S3. For Azure, provide the production connection string and container outside the Compose defaults.

Runtime trust boundaries

FastAPI uses one Uvicorn worker because mounted FastMCP apps and lifecycle tasks are process-local. Do not increase the worker count without changing the runtime architecture.

The trusted runner controls Docker and has access to the Docker daemon socket. It is not exposed as a host port and must only be run on a host you trust. Tool code runs in an ephemeral non-root sandbox with no Docker access, host mounts, or deployment credentials. The per-call network includes only the sandbox and its egress proxy; the proxy resolves destinations and rejects non-public IP addresses.

Use HTTPS, strong credentials, private database and storage networks, and carefully scoped access. Never share authenticated Inspector URLs, bearer tokens, workspace secrets, or redacted logs containing credentials.
